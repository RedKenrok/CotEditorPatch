# Design

Each patch has its own design document, with its evidence:

- [Patch 1: directory file tabs](01-tabs.md), the tab-system foundation. It applies to plain upstream.
- [Patch 2: shell tabs](02-shell.md), a new kind of tab, in an unsandboxed app. It applies on top of patch 1.
- [Patch 3: web pages](03-webpage.md), webpage tabs for HTTPS sites and local development servers. It applies on top of patches 1 and 2.
- [Patch 4: remote files](04-remote.md), editing files on SSH servers over SFTP. It applies on top of patches 1 to 3.

Each app is built from a prefix of the series, as described in [AGENTS.md](../AGENTS.md#layout), so a patch's code needs no compilation condition. Each patch's test changes are in a file of their own, in `patches/tests/`.

Everything planned for patch 4 is implemented, including opening remote folders, changing their items and terminals in them; what was decided against is listed under [its known limitations](04-remote.md#known-limitations).

Patch 1 is the complete foundation of the tab system and stays buildable and usable on its own. It includes the contract for tabs that are not files, which every later kind of tab goes through, proven in its tests with a fake kind. Patch 2 only adds a new kind of tab on top of it, and changes 4 existing lines. Patch 3 adds another kind of tab the same way, and changes 2 existing lines: the registered kinds and the bundle identifier. Patch 4 adds a new kind of document, not a new kind of tab: a remote file is a `Document` in an ordinary file tab. It changes 28 existing lines, most of them in splitting two helpers out of `Document`'s save path. Its remote folder windows are directory windows with a root, patch 1's hook for a folder that is not on this Mac.

## Which patch is responsible for what

| Area | Patch 1 | Patch 2 | Patch 3 | Patch 4 |
| --- | --- | --- | --- | --- |
| Applies to | Pinned upstream | Pinned upstream + patch 1, exactly as exported | Pinned upstream + patches 1 and 2, exactly as exported | Pinned upstream + patches 1 to 3, exactly as exported |
| Tab model | `DirectoryTabState`, entries, selection, neighbor-on-close, `arrange(by:)`; tabs that are not files are `.item` entries of the `DirectoryTabItem` contract, and `reconcile` keeps them in place | None: terminals are items | None: webpages are items | None: remote files are file entries |
| Tabs that are not files | `DirectoryTabItem` and `DirectoryTabKind`: presentation, a controller cached per tab, an optional close approval, a review notice, teardown after every approval, archive by kind, **+** and context menu items; open, select, close and remove in `DirectoryDocument+TabItems`; proven with a fake kind | `TerminalSession` and `DirectoryTabKind.terminal` | `WebPageSession` and `DirectoryTabKind.webPage` | `DirectoryTabKind.remoteFile`, whose tabs are member documents restored through `restoreDocuments` |
| Members | Registry of member documents; `adoptMember(_:tabID:select:)` attaches a document that is already open, including one without a file | None | None | Remote documents join through `adoptMember` |
| Folders elsewhere | `DirectoryRoot`: a directory window without a file URL, whose root gives the title, subtitle and sidebar, gets the window's state changes and close, and restores its tabs (`tabArchive`, `restoreTabs(fromArchive:)`, with file tabs off its member documents); New File only through a root that can create files | Local terminals of a folder elsewhere in the home folder, and the root's own through its `TerminalLauncher` (`TerminalLaunchProviding`), with a **+** menu item it names | None: webpages need no folder | Remote folder windows: `RemoteFolderSession` as the root, `RemoteFileBrowserViewController`, `RemoteDirectoryTree`, the folder identity, one window per folder, creating, renaming, moving and deleting items (`RemoteFolderChanges`), terminals on the server (`RemoteTerminal`), changed-location review, offline restoration from `RemoteFolderArchive` |
| Tab strip | `DirectoryTabBar`, presentations read from overridable `DataDocument` properties (title, tooltip, icon, badge) or the item, accessibility labels, a **+** menu with **New File** and the kinds' items (which can be disabled), dragging to reorder, dragging out or **Move to New Window** to give a file its own window, and a per-tab context menu | **New Shell** in the **+** menu, **Rename…** in the context menu of shell tabs, terminal presentation (icon, tooltip naming the starting folder) | **New Webpage** in the **+** menu, **Clear Website Data…** in the context menu, webpage presentation (globe, page title, address tooltip) | **Remote File…** and **Remote Shell** in the **+** menu; remote presentation (`user@host:/path` tooltip, no badge) |
| Content host | Editor cache, viewport restoration, file and empty switching, focus hand-off, one routine that detaches the hosted controller, hosting an item's controller in place of any document | The terminal controller | The webpage controller: web view, navigation bar, message bar, placeholder | None |
| Commands | ⌘W closes the selected tab, whatever it shows; File > Close Window (⇧⌘W); Window > Show Previous Tab (⌘⇧[) and Show Next Tab (⌘⇧]), and ⌘1 to ⌘9, walk the tabs; file-only actions use `activeFileDocument` | New Shell Tab, Rename Shell Tab…, the file browser's Open Shell Here | New Webpage Tab | Open Remote File…, Open Remote Folder…, Open Recent Remote Folder, New Remote Shell Tab, Save a Local Copy…, Revert to Remote Version (Reconnect for a placeholder); Save As… is Save As Remote |
| Documents | `DataDocument` presentation and archive properties, which tabs, the window subtitle and the archive read | None | None | `RemoteDocument`, a `Document` subclass with `fileURL == nil`; `Document` loses `final` and gains `prepareForSaving(for:)` and `encodedContents()` |
| Settings | File tabs toggle in Window settings | Terminal settings pane: theme, program colors and notifications from programs | None | None |
| Close and quit | Dirty-file approvals for tab close, window close and Close All, through one replaceable approval function; each kind's window approval first; teardown only after every approval | Running-terminal consent through the kind; quit consent in the document review | None: webpages never ask; website dialogs are dismissed before a review | The remote close review (Save, Keep Recovery Copy, Discard Changes, Cancel) through the same approvals; records kept for restoration while quitting |
| Preference | `usesDirectoryFileTabs` (default off) and its observer, which closes every item when tabs turn off | Confirmed "turn tabs off" transition in Settings | None | With tabs off, remote files open in windows of their own |
| Restoration | Versioned archive (version 1) holding tabs of every kind in one order; files reopen here, entries of other kinds go to the registered kinds (`foreignEntries`, `restoreForeignTabs`) | Terminal entries (kind `terminal`) as inactive placeholders | Webpage entries (kind `webpage`) as placeholders that load only when asked | Remote entries (kind `remoteFile`) reopened offline from their recovery records, or as placeholders; standalone windows, remote folder windows (offline, from their own records) and a recovery list at launch |
| Web pages | None | None | Navigation policy (HTTPS, local HTTP), retry and resubmission rules, website dialogs, website data | None |
| Remote files | None | None | None | `ssh` launch with jump hosts, askpass questions and host key trust, SFTP client with folder listing, save state machine, recovery store, connection pool with a browsing role, open sheet, folder browser, inspector section |
| Build, signing, dependency | None | The Shell app's bundle identifier, upstream's entitlements without the App Sandbox and iCloud, SwiftTerm 1.20.0, SwiftTerm license notice | The Web app's bundle identifier, `NSAllowsLocalNetworking`; the system's WebKit | The Remote app's bundle identifier, and its askpass program among the command-line tools; no package |
| Strings | Upstream `Document` and `WindowSettings` tables, with translations | `Terminal.xcstrings`, English only | `WebPages.xcstrings`, English only | `Remote.xcstrings`, English only |
| Tests | `DirectoryTabTests`, `+Viewport`, `+Items`, `+Root`, `DirectoryTabArchiveTests` | `TerminalSessionTests`, `TerminalColorsTests`, `DirectoryTabTests+Terminal`, `TerminalPTYTests` | `WebPageNavigationPolicyTests`, `WebPageSessionTests`, `DirectoryTabTests+WebPage` with a local HTTP server | `RemoteSFTPCodecTests`, `RemoteTransportTests`, `RemoteRecoveryTests`, `RemoteSaveTests`, `RemoteDocumentTests`, `RemoteDirectoryListingTests`, `RemoteDirectoryTreeTests`, `RemoteFolderPickerTests`, `RemoteFolderChangeTests`, `RemoteAskpassTests`, `RemoteTerminalTests`, `DirectoryTabTests+Remote`, `DirectoryTabTests+RemoteFolders`; real-server tests with `scripts/remote-fixture.sh` |
